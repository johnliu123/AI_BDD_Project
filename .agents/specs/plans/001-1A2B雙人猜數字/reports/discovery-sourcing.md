## Impact scope

- 本輪問題一句：新增一款支援雙人線上對戰的 1A2B 猜數字遊戲，涵蓋配對、秘密數字設定、設定前修改、猜測回饋與勝負結束。
- 納入範圍：遊戲 ID 與玩家名稱輸入驗證、建立或加入遊戲、滿房與重複加入阻擋、雙人滿員後進入設定秘密數字、P1/P2 依序設定秘密數字、秘密數字與猜測格式驗證、猜題階段啟動、猜測產生幾A幾B回饋、4A 勝利與結束狀態。
- 明確排除：帳號登入、觀戰、排行榜、斷線重連、聊天室、計時器、AI 對手、前端視覺版型、實際網路傳輸協定與資料庫 schema 細節。

## Function package charters

### `packages/01-雙人猜數字對戰`

- **職責一句**：承載玩家從進入同一場遊戲、設定秘密數字到互猜並結束對戰的完整對外行為主線。
- **納入**：進入遊戲配對、設定秘密數字、修改秘密數字、提交猜測與判定勝負。
- **排除**：帳號系統、排行榜、觀戰、聊天、斷線重連與非 1A2B 核心規則。
- **本輪變更型態**：`new-package`
- **本輪規格增量**：建立雙人 1A2B 對戰的初始 feature 與 atomic rules。

## Packaging decision

- 新 plan package：`001-1A2B雙人猜數字`
- 本輪涉及的 function packages：
  - `packages/01-雙人猜數字對戰`（`新開`）
- function package 決策：本輪需要新開 function package，原因是需求描述的是一條完整且單一的對外遊戲生命週期：建立或加入遊戲、設定秘密數字、猜測與結束。

## Resolved sourcing decisions（已拍板）

- 以單一 function package 承載整場對戰生命週期：**是**；依據是原始需求從配對到結束皆圍繞同一場 1A2B 對戰狀態。
- 將「進入遊戲配對」「設定秘密數字」「修改秘密數字」「提交猜測」拆為 Feature Files：**是**；依據是這些都是玩家可獨立觸發且可獨立驗收的行為。
- 將「進入猜題階段」視為設定秘密數字完成後的狀態轉換：**是**；依據是原始需求寫明系統偵測兩位玩家皆已設定好答案時自動進入猜題階段。

## Notes

- 需求原文未定義回合先手、猜題階段是否嚴格輪流、猜錯後下一位如何輪替；本輪僅收斂已明示的猜測輸入驗證、A/B 回饋與 4A 結束規則。
